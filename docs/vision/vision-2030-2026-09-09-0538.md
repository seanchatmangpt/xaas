# Vision 2030 — Cycle 2026-09-09-0538

## Charter (grounded: closing HDDL's own disclosed "second half" gap, for real)

`docs/hddl/README.md` has stated, since it was written this session, an honest
disclosed gap: "no HTN planner currently consumes these files... this is the
Operationalize step's *first* half — writing the fixed method down — not yet the
second half (a planner or script that executes it without an LLM re-deriving the
decomposition each time)." Six hourly cycles have run since then, each still having
an LLM (a Workflow's `Verify` stage agent) re-derive the exact same
compile→migrate→test→mock-grep→commit sequence from `verify-and-commit.hddl`'s prose
description every single time. That is real, observed, repeated LLM-reasoning cost on
an already-fully-known, already-formalized task class — exactly the waste the
doctrine's central axiom ("intelligence succeeds by reducing the intelligence needed
next time") names directly.

**This cycle's real, scoped goal**: build `mix xaas.workflow.verify_and_commit`, a
real, fixed, compiled Elixir Mix task implementing `verify-and-commit.hddl`'s method
exactly (compile --force → ecto.migrate → test → mock-grep → git commit -F) as real
code — not a paper method, not a re-parsed HDDL file, a real running executor. Future
workflow scripts' Verify stages can shell out to `mix xaas.workflow.verify_and_commit`
instead of an LLM re-deriving the 5-step sequence in prose each time. This is real,
minimal Operationalize-second-half work, scoped to exactly the one domain
(`verify-and-commit.hddl`) that's simplest and most repeated (6+ real instances this
session already).

## Real design constraints (from real project conventions, not invented)

- Must accept real, explicit arguments (a commit-message file path, real test-path
  globs, real DB env vars already used everywhere else in this repo) rather than
  hardcoding assumptions — every prior cycle's verify stage varied these slightly.
- Must NOT swallow/hide a real failure — if compile fails, the task must halt with a
  real non-zero exit and the real error output, not proceed to commit anyway (this
  repo's Operating Mode says don't GATE work on green tests across cycles, but a
  single verify-and-commit invocation must still honestly reflect what happened).
- Must NOT auto-push — commit only, matching every prior cycle's real behavior
  (push has always been a separate, explicit step this session).

## Size target

~50 minutes via real depth: 8-12 research lenses on the real, exact shell commands

the commit message file doesn't exist), 3-skeptic adversarial verify, 5+ real

failure scenarios (a deliberately broken file to prove compile-failure halts commit).
