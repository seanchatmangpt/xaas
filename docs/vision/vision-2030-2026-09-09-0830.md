## Charter: close the real `--warnings-as-errors` gap blocking `mix xaas.verify_and_commit`

**Real, grounded finding** (from cycle 0738's own honest disclosure, re-confirmed
live just now via `mix compile --force --warnings-as-errors 2>&1`): the new
`mix xaas.verify_and_commit` task cannot pass on this repo's live tree because its
`compile` stage uses `--warnings-as-errors` (stricter than the plain `mix compile
--force` used elsewhere), and 2 pre-existing typing warnings fail that gate:

- `lib/xaas/library/reactors/steps/score_book.ex:84`
- `lib/xaas/library/embedding_models/local_nx.ex:42`

**Real root cause** (confirmed by reading `lib/xaas/library/embeddings.ex` directly,
not guessed): `Xaas.Library.Embeddings.embed/1` has exactly one real clause
(`when is_binary(text)`) whose body always returns `{:ok, vector}` — it can never
actually produce `{:error, _}` (a non-binary argument raises `FunctionClauseError`
instead). Elixir's set-theoretic type checker infers the real success type
`dynamic({:ok, term()})` from the function body, which is more accurate than the
`@spec`'s aspirational `{:ok, ...} | {:error, term()}`. Both call sites
(`score_book.ex`, `local_nx.ex`) match on an `{:error, reason}` clause that is real,
literal dead code given the actual implementation — hence "this clause will never
match."
