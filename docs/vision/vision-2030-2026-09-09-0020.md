# Vision 2030 — Cycle 2026-09-09-0020

## Charter (grounded in real repo state, not invented)

This cycle's scope is derived from real findings already surfaced this session — not a
speculative theme. Three real, evidenced problem classes drive it:

**RCA (root cause, observed directly this session):** launching multiple concurrent
`Workflow` runs against the same working tree caused real, reproducible `mix compile`
build-lock contention — agents blocked on `Waiting for lock on the build directory`,
some unable to complete verification at all (`next-read-finish-orthogonal`'s
`checkout-actuation-wrap` and `library-policy-hardening` tasks both reported this
verbatim). Root cause: no serialization discipline between concurrently-launched
workflows sharing one `_build`/`deps` directory, compounded once by a stray
asdf-Elixir-1.18 process racing a homebrew-Elixir-1.19 compile on the same tree
(diagnosed and killed this session, but the underlying serialization gap remains).

**FMEA (failure mode, evidenced):** the A2A agent's `as:<user_id>` actor resolution
(`lib/xaas_web/a2a/next_read_user_agent.ex`) has a disclosed, unmitigated impersonation
failure mode — any bearer-token holder can assert any user id. Severity: real
(unauthorized action-as-another-user); current detection: none (no audit trail ties an
A2A caller's real identity to the actor it asserted); current mitigation: documentation
only. This is the highest-severity real, open finding from this session's adversarial
ERRC review not yet closed by code.

**ERRC (from this session's ERRC review, `xaas-agi-2030-errc-review` workflow):**
- *Raise*: `Checkout.borrow`'s actuation coverage — CLOSED this session (wrapped through
  `Xaas.Actuation.run/4` with idempotency key, real test added). Verify it lands clean.
- *Raise*: Ash policy floor on Library resources (was `authorize_if always()` on every
  action) — landed this session (tightened to `actor_present()` on mutations). Verify.
- *Create*: no real audit binding an A2A/MCP caller's actual credential to the actor it
  claims. Not yet built. This cycle's primary *Create* target.

## This cycle's concrete charter

1. **RCA fix**: add a real, lightweight workflow-serialization discipline for this repo
   — a lockfile-based guard (e.g. `.claude/workflow.lock` with PID + timestamp) that a
   `Workflow` script's first agent checks/writes before doing concurrent `mix compile`
   work, so future sessions don't reproduce this session's build-lock contention. Keep
   it simple: a real file-based mutex, not a new service.
2. **FMEA fix (primary)**: build a real, minimal binding between an A2A/MCP caller's
   actual authenticated credential and the actor it may assert. Given this repo's one
   real auth primitive is the shared `INTERNAL_API_TOKEN` (per
   `ResolveOrgActor`'s own disclosed design), the smallest real improvement is: a
   real, persisted `Xaas.Library.PersonaGrant` (or similarly named) resource mapping a
   caller-scoped credential to an allow-list of user ids it may act as, checked by
   `NextReadUserAgent.resolve_actor/1` before threading the actor through — turning
   silent impersonation into an explicit, auditable, denyable grant. If a full grant
   resource is too large for one cycle, land the audit-trail half first (log every
   `as:<user_id>` resolution to a real `Xaas.Operations.AuditLogEntry` row) and name the
   grant-enforcement half as carried-forward, explicitly, in the results doc below —
   do not claim the full fix if only the audit half lands.
3. **Verification via avatars**: use the real MCP (`/mcp`) and A2A (`/a2a`) surfaces to
   simulate at least 3 distinct Next Read personas (e.g. a real student actor, a guest/
   unauthenticated actor, and an actor attempting an unauthorized impersonation) as real
   Chicago-style tests — real HTTP/GenServer calls against the real Ash-backed app, no
   mocking of MCP/A2A internals — proving the new binding actually denies the
   impersonation avatar while the legitimate avatars still work.

## Explicitly out of scope this cycle
