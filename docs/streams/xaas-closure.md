## Gate

### Compile

At base, `mix compile --warnings-as-errors` exited 1 on three warnings in `lib/`. Each was a
real defect, not noise:

1. `lib/xaas/castle.ex` `Kernel.CLI.manufacture/2` and `verify_runtime_checkpoint/5` called
   `Atom.to_string(contract.protocol)`. `Xaas.Castle.Contract.identity/0` returns the protocol
   as a binary (`"CASTLE_PAAS_XAAS_BRIDGE_V1"`), so `Atom.to_string/1` raises `ArgumentError`
   at runtime on the first CASTLE manufacture. Fixed by using the binary directly.
   `test/xaas/castle_bridge_test.exs` asserted `is_atom(contract.protocol)`; corrected to
   `is_binary/1`. That test needs the `:castle_kernel` tag and a CASTLE binary, so it was not
   executed here (UNVERIFIED at runtime; the compile-time type check is the evidence).
2. `lib/xaas/semantics/computation.ex` `RuntimeEquivalence.qualify/3` declared a default
   argument on a multi-clause function. Fixed with a function head.

The remaining warning in the compile output is in `deps/ex4pm/mix.exs` (a dependency), not in
this repo.

were formatted in place. Three files under `lib/xaas/generated/` (`sa2a_bridge_contract.ex`,

ggen-marketplace/sa2a-bridge-pack ... Do not hand-edit`. They are excluded from the formatter
