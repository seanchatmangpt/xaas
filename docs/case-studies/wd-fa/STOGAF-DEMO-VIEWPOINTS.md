# WD CS2 Demo — STOGAF Viewpoint Map

The demo package is one architecture subject projected for different stakeholder concerns.

```
                         O*
                          │
          ┌───────────────┼────────────────┐
          ▼               ▼                ▼
     FA engineer      Executive        Architecture
          │               │                │
          ▼               ▼                ▼
   Morning Brief      Board Deck       System / Space
          │
          ▼
     Case detail
```

## Operator viewpoint

**Projection:** FA Morning Brief  
**Question:** What requires me now?

The operator view SHOULD prioritize:

- cases requiring disposition;
- BLOCKED / UNKNOWN subjects;
- missing evidence;
- next lawful action;
- owner;
- authority boundary;
- provenance/deep link.

It SHOULD suppress already-derived context that does not require operator reconstruction.

## Executive viewpoint

**Projection:** FA Agent Board Deck  
**Question:** Is the operating system reducing repeated investigative work without weakening control?

It SHOULD emphasize:

- throughput;
- blocked work;
- repeated work eliminated;
- false-KNOWN / false-UNKNOWN risk;
- adoption;
- evidence-backed business outcomes;
- explicit non-claims.

## Architecture viewpoint

**Projection:** System / Space  
**Question:** What is canonical, generated, governed and reusable?

It MUST distinguish:

- O* canonical state;
- generated views;
- sJira work projection;
- SA2A capability interaction;
- SELECT / CONSTRUCT / DO;
- verification receipts;
- MachineExperience.

## Assessment viewpoint

**Projection:** WD Case Study 2 Deck  
**Question:** Does the system answer the stated brief and expose its assumptions, tradeoffs and evidence ceiling?

The assessment view maps each WD requirement to:

```
requirement
→ architecture element
→ implementation
→ falsifier
→ court
→ standing
→ presentation evidence
```

## Deep-link rule

Every interactive view SHOULD be capable of carrying a context envelope sufficient to reconstruct:

- subject identity;
- viewpoint;
- standing;
- evidence references;
- work identity;
- authority ceiling;
- replay identity where applicable.

## Demo sequence

The recommended live sequence is:

1. show the Morning Brief and the few items requiring human judgment;
2. open a KNOWN case and show deterministic admission;
3. open a PARTIAL case and show missing evidence;
4. open UNKNOWN and show candidate-without-authority;
5. admit the verified MachineExperience fixture;
6. replay the exact class as KNOWN;
7. show STOGAF architecture standing;
8. show that ST-7+ remain unclaimed.
