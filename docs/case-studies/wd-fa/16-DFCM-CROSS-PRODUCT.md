# DfCM Cross-Product

Design for Combinatorial Maximalism asks us to compose existing capabilities rather than build isolated local solutions.

## Four design inputs

### WD

Provides the explicit case requirements:

- grounded ranked failure modes;
- multimodal historical FA;
- structured/unstructured joins;
- traceability;
- known vs novel;
- human loop;
- evaluation;
- MTTR and delivery plan.

### Toyota/TPS reference structure

Provides the quality-system structure missing from the intentionally incomplete prompt:

```
standard
→ abnormality
→ work
→ disposition
→ verified countermeasure
→ improved standard
```

Toyota is a structural prior only; the case remains WD Case Study 2.

### Sony/FDE reference

Adds:

- end-to-end ownership;
- full-stack delivery;
- handoff;
- reusable platform capability;
- compounding across engagements.

### Qvest execution precedent

Adds:

- explicit evidence boundaries;
- human authority;
- runnable vertical slice;
- receipts;
- offline→shadow→pilot evaluation;
- executive decision ask.

## Cross-product result

```
WD requirement
× quality operating loop
× reusable FDE platform
× evidence-bounded executable delivery
=
STOGAF WD CS2 architecture episode
```

## DfCM rule

New local code is justified only when no existing ecosystem capability can lawfully express the requirement.

Prefer:

```
compose → constrain → project → verify
```

over:

```
invent → duplicate → hand-maintain
```
