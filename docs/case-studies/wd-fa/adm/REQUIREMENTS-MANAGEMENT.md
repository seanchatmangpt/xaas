# Continuous Requirements Management

Requirements management runs through every phase.

## Requirement state

A requirement has:

- identity;
- source;
- architecture building block;
- implementation projection;
- evidence required;
- verification court;
- standing;
- unresolved gap.

## Friday policy

No requirement is considered closed solely because prose exists.

A requirement may be:

```
DESIGN
PARTIAL_ALIVE
ALIVE_FIXTURE
UNKNOWN
BLOCKED
REFUSED
```

The presentation uses the same standing vocabulary and must not promote a requirement beyond its executable evidence.
