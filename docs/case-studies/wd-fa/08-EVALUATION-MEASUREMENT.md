# Evaluation and Measurement

Evaluation has three distinct stages.

## Offline / repository court

Prove mechanics:

- known case admitted;
- incomplete evidence remains PARTIAL;
- novel case remains UNKNOWN despite candidate ranking;
- misleading similarity cannot override deterministic applicability;
- tampered receipt fails;
- verified MachineExperience changes the exact future class to KNOWN;
- browser projection matches domain state;
- architecture standing does not exceed evidence.

## Shadow evaluation

Using authorized historical/parallel WD cases, measure:

- retrieval recall;
- candidate ranking quality;
- false-KNOWN;
- false-UNKNOWN;
- evidence completeness;
- prior-case applicability;
- diagnostic-action usefulness;
- engineer override;
- disposition agreement;
- time to reconstruct context.

## Production pilot

Only after shadow admission, measure:

- MTTR;
- time to containment;
- time to verified disposition;
- engineer touches per case;
- exploratory steps per case;
- repeated investigations avoided;
- MachineExperience reuse;
- recurrence rate;
- false-known escape rate;
- time to corrective action.

## Causal caution

A lower MTTR after rollout does not automatically prove the agent caused the improvement. Deployment, staffing, workload mix, hardware population and policy changes may confound results.

The proposal SHOULD therefore define a baseline, cohort, comparison method and guardrail metrics before claiming improvement.
