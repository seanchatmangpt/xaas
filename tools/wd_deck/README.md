# WD deck manufacture

The PowerPoint is generated. Do not hand-edit the generated `.pptx` as a source artifact.

```text
docs/case-studies/wd-fa/presentation/deck.ttl
  -> pptx-presentation-pack @ immutable ggen-marketplace commit
  -> ggen_igniter
  -> deck.json + render fragments
  -> deterministic render.mjs assembly
  -> PptxGenJS 4.0.1
  -> .pptx + speaker notes
  -> OOXML verification receipt
```

## Install the Typer CLI

```bash
python3 -m venv .venv-wd-deck
. .venv-wd-deck/bin/activate
pip install -e tools/wd_deck
wd-deck bootstrap
```

`bootstrap` installs only the exact Node renderer dependency declared in `tools/wd_deck/package.json`.

## Regenerate

Full 14-slide deck including the two internal presenter-prep slides:

```bash
wd-deck render --audience all
```

Interview projection only (12 slides; internal prep excluded):

```bash
wd-deck render --audience interview
```

Use a local marketplace checkout explicitly:

```bash
wd-deck render \
  --pack-dir ../ggen-marketplace/packs/pptx-presentation-pack \
  --audience all
```

The CLI resolves the pack in this order: explicit `--pack-dir`, `GGEN_PPTX_PACK_DIR`, then sibling `../ggen-marketplace/packs/pptx-presentation-pack`. The expected marketplace commit is pinned in `wd_deck.py`; CI materializes that exact commit before manufacture. If no admitted local pack is present, the CLI fails closed with `BLOCKED:PACK_NOT_MATERIALIZED` rather than silently following a moving branch.

## Commands

- `wd-deck bootstrap` — install the pinned PptxGenJS runtime.
- `wd-deck sync` — manufacture `deck.json` and renderer fragments through `ggen_igniter`, then assemble `render.mjs`.
- `wd-deck render` — sync, render PPTX, verify OOXML, emit receipt.
- `wd-deck verify` — independently verify a generated PPTX against the generated deck spec.
- `wd-deck inspect` — print the semantic slide projection.

## Standing

A successful receipt establishes only repository-local generation standing for the exact ontology, marketplace pack commit, `ggen_igniter` path, PptxGenJS version and generated bytes. It does not establish WD acceptance, production deployment, customer authority, or external standing.
